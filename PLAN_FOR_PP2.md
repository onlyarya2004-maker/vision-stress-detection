# Plan for PP2 — Vision-Based Behavioral Stress Detection v2

> Master plan agreed August 2026, based on a full audit of the PP1 codebase, the PP1 report
> (NEWFINALONPP1.pdf) and the research paper (RESEARCH_PAPER_PP1_3.0.pdf).
> Goal: make the project genuinely AI-powered at the decision layer, close the
> video-vs-physiology gap, fix every credibility issue found in the audit, and ship the
> strongest possible PP2.

---

## Hard constraint

**Visual monitoring only.** No wearables, no contact sensors, nothing physical on the user —
ever, including during development. The runtime system is strictly:
`webcam → MediaPipe landmarks + CNN + rPPG (all computed from pixels) → fusion → LOW/MOD/HIGH`.

Datasets recorded *by other researchers* with sensors (WESAD, UBFC-Phys) are fine to use
offline as reference/validation data — that does not make our system sensor-based. rPPG is
camera-only by definition (it reads the pulse from skin-color changes in the video).

## Problems found in the PP1 audit

> **We are NOT editing the PP1 report or paper.** They are already submitted; editing them
> buys nothing. This section is **carry-forward knowledge**, for two purposes:
> (1) viva/defense preparation — know which numbers are actually real if questioned;
> (2) a list of claims the CODE should honestly support going forward, and mistakes not to
> repeat in any future write-up.

### Critical
1. **The "13 unit tests" described in both the paper (Sec. VII) and report (Sec. 4.3.1,
   Table 4.2) do not exist.** No test file exists anywhere in the project. Either write them
   (the documents are effectively a ready-made spec) or remove the claim.
2. **Headline accuracy numbers are internally inconsistent.** Verified by re-running
   `analyze_sessions.py` on the real CSVs:
   - Default mode (n=176): **98.9% is the real, reproducible number** (gap +0.292,
     recall 100%/98.4%). The report contains BOTH 88.37% (Abstract, Table 5.1, Conclusion)
     and 98.9% (Fig 5.5, Sec 5.1, Appendix B) for the same configuration. The paper uses
     88.37% throughout. Pick the reproducible number, use it everywhere.
   - Studying mode (n=293): **94.5% is real** (from studyrelaxed/studystressed CSVs in
     baseline_v1). Report/paper sometimes say 87.2%.
   - "May 2 baseline n=202": `evaluation_data/baseline_v1/` currently holds 468 pooled rows
     and reproduces 83.8% — matches none of the claimed numbers (89.6% / 84.8%). Either
     regenerate that baseline or drop the comparison row.
3. **WESAD accuracy: 91.86% is the real number** (it is in `models/calibrated_thresholds.json`
   and `wesad_calibration_report.txt`, generated by the current code). The entire research
   paper uses 85.56%, and the paper's WESAD methodology description ("mean and std of each
   channel") describes an older, simpler version — the real code does bandpass-filtered R-peak
   HR/HRV, EDA tonic/phasic decomposition with SCR counting, and respiration-rate detection.
   The real pipeline is *better* than what is written; fixing this strengthens the paper.

### Also broken / misleading
4. Report Sec. 3.1.1 says face crops use a **Haar cascade** — false; it is MediaPipe FaceMesh
   everywhere in the code.
5. `evaluation_data/relaaxed_2.csv` (typo'd filename) is **silently excluded** from every
   reported number because the analyzer globs `relaxed_*.csv`. It holds 48 valid all-LOW
   relaxed samples. Rename it → true Default-mode n becomes 224.
6. The report claims "Using Git with meaningful commit messages" — **the project is not a git
   repository.**
7. **No `requirements.txt`** (only a pip line in the README).
8. The thresholds story is half-true: `stress_fusion.py` hardcodes 0.36/0.55 and only reads
   the smoothing window from `calibrated_thresholds.json`; the JSON's own WESAD-derived
   cutoffs (0.029/0.683) are ignored. The 60-frame smoother (~2 s) also ignores the JSON's
   recommended 11.1 s window. Documents must describe what the code actually does.
9. Report Appendix A code excerpts are paraphrased, not literal (different column names etc.).
   Labeled "representative" so acceptable, but be aware.
10. Frame-level pooled accuracy overstates the evidence: 176 "samples" are autocorrelated
    frames from 3 recordings. Report session-level results and confidence intervals too.

### What held up
Architecture description, fusion math (weights, task-mode multipliers, rule boost,
smoothing/hysteresis constants), the FER2013 negative result, the LSTM negative result, and
the honest-limitations sections all match the code exactly. Keep all of it.

## Why PP1 is not yet "AI-powered" at the decision layer

- The DaiSEE CNN ensemble is real AI but carries only **20%** fusion weight.
- The behavioral engine (80% weight) is hand-tuned formulas over MediaPipe landmarks.
- Fusion weights (0.20/0.80), the +0.12 rule boost, and thresholds (0.36/0.55) are all
  **hand-picked constants** (archived comments literally say "reverted to yesterday
  morning's value").
- The one trained temporal model (LSTM) is **disabled** (W_LSTM = 0.0) because it scored
  71.1% vs. an 86.6% majority-class floor — root cause: frozen ImageNet features carry no
  stress signal.

PP2 fixes this by making the decision layer *learned* (Phase 3), adding a genuinely
physiological camera-only branch (rPPG, Phase 2), and retraining the temporal model on
stress-relevant features instead of raw pixels (Phase 2).

## Phase 0 — Foundation & credibility (~1 week) — DO FIRST, NON-NEGOTIABLE

- [ ] `git init` + initial commit immediately. Stop making copy-folder backups going forward
      (keep existing `_archive/` and `BACKUP_DEMO_FINAL/` for history).
- [ ] Write `requirements.txt` (pin the exact known-good stack: streamlit==1.30,
      tensorflow==2.15.0, mediapipe==0.10.14, protobuf==4.25.3, numpy==1.26.4, opencv-python,
      scikit-learn, pandas, scipy) + separate `requirements-train.txt` for new PyTorch work.
- [ ] Rename `relaaxed_2.csv` → `relaxed_2.csv`. Decide fate of `baseline_v1/` (regenerate or
      drop). Run `analyze_sessions.py` once → freeze as the canonical "before" numbers.
- [ ] Write the unit test suite in pytest — the 13 tests the documents already describe:
      schema creation, idempotent re-init, save/load round-trip, cascade delete, v2→v3
      migration, Default-mode equivalence (assert diff < 1e-9 vs. baseline math), smile
      heuristic, pose-visibility gate, hand-near-face damping.
- [ ] **Centralize config + fix the dishonest threshold path** (audit finding #8, at code
      level). Currently `_load_calibration()` reads `calibrated_thresholds.json` and then
      discards its WESAD cutoffs (0.029/0.683) in favour of hardcoded 0.36/0.55; and the
      JSON's `recommended_window_seconds` (11.07 s) loads into `_CAL['window_s']` but is
      **dead code** — both `app.py` and `stress_detector.py` pass an explicit `window_size=`
      that overrides it. Fix: pull every magic constant into one `config.py`/YAML
      (cutoffs, W_DAISEE/W_BEHAVIOR, BEHAVIOR_AMPLIFICATION=1.2, RULE_BOOST_AMOUNT=0.12,
      ACTIVE_SIGNAL_THRESHOLD, DaiSEE deviation_scale=0.15, SMOOTHING_WINDOW,
      CNN_EVERY_N_FRAMES, behavioral-engine divisors). Make JSON loading either genuinely
      functional or explicitly removed — no code that pretends to load values it discards.
      Payoff: Phase 3's learned params become drop-in; Phase 4 ablations become config
      sweeps, not source edits.
      *Note for Phase 3:* the WESAD cutoffs are unusable as-is because they are percentiles
      of a logistic-regression probability distribution over physiological features — a
      different scale from the vision-fused stress index. Percentile-matching across two
      unrelated distributions is not principled; learned thresholds are the honest fix.
- [ ] **Build the evaluation harness NOW, not in Phase 4.** `run_all_evaluations.py` writes
      one timestamped results file. At Phase 0 it covers Default mode, Studying mode, and the
      DaiSEE/WESAD artifact numbers. Includes Wilson 95% CIs on every accuracy
      (`proportion_confint(count, n, method='wilson')`) and **session-level verdicts
      alongside frame-level** (176 frames come from only 3 recordings — frame-level n
      overstates the evidence). Later phases add rows: rPPG ablation, multi-subject
      breakdown, learned-vs-hardcoded fusion. This is the permanent structural fix for the
      number-drift that made PP1's results unreproducible.
- [ ] **Recording protocol + naming helper** (before Phase 1's multi-subject work). Write the
      exact steps down (calibrate → 60 s relaxed → restart → 60 s stressed, with the specific
      stress behaviours used) and a helper that auto-names exports
      `{subject}_{condition}_{mode}_{date}.csv` so provenance is baked into the filename.
      Without this, Phase 1 produces another `baseline_v1/` that nobody can reconstruct.
- [ ] GPU smoke test: RTX 5070 Ti + native Windows TF 2.15 = CPU-only dead end. Use
      **PyTorch** for all new models (`torch.cuda.is_available()` must pass). Set Python to
      "High performance NVIDIA GPU" in Windows Graphics Settings.

## Phase 1 — Datasets & multi-subject evaluation (~1.5–2 weeks)

- [ ] **UBFC-Phys** (56 subjects, induced-stress protocol, synchronized frontal video +
      EDA/BVP). Request access EARLY — research datasets often have license turnaround.
      Two uses:
      1. Independent validation: run the existing system on its videos, correlate our stress
         index with its physiological stress signal. First-ever video-grounded physiological
         validation of the system.
      2. (Stretch) fine-tune the CNN on it alongside DaiSEE — its labels come from real
         induced stress, not a derived engagement formula.
      3. Bonus: validate the Phase-2 rPPG module against its BVP ground truth — **no physical
         device needed, ever**.
- [ ] **Multi-subject evaluation using the team.** 4 team members + willing classmates each
      record calibrate → relaxed → stressed sessions (~2 h/person). Converts the papers' #1
      admitted limitation (single-subject) into a new results table, and finally tests the
      claim that personal calibration gives cross-user robustness.
      Requires multi-user profiles (Feature 2) or disciplined per-subject file naming.
- [ ] (Stretch, at most one) **SWELL-KW** — knowledge-worker stress with video + posture +
      interaction logs → grounds the Studying mode multipliers in real data. (Alternative:
      BioVid Heat Pain for Hospital mode — lower priority.)

## Phase 2 — Temporal model + new AI branches (~2 weeks)

- [ ] **Replace the LSTM: feed features, not pixels.** Run MediaPipe over the existing
      `processed_daisee/` crops → per-clip behavioral-feature sequences (16 × ~10 dims:
      EAR, brow, jaw, blink, head, etc.). Train a small GRU(32) or 1D-TCN → sigmoid.
      Minutes per run on GPU. Baseline ablation: gradient-boosted trees on windowed summary
      stats (mean/std/slope) — sometimes beats RNNs on small noisy-label data; good paper
      ablation either way. Budget for it possibly still underperforming — document honestly
      whichever way it goes.
- [ ] **rPPG heart-rate branch (camera-only — flagship addition).** Remote
      photoplethysmography: extract pulse from skin-color changes in the face ROI (POS/CHROM
      algorithm or pyVHR). ~10 s rolling window, FFT peak → HR estimate. Score HR deviation
      from calibrated resting HR against WESAD's distributions (baseline ≈72 bpm vs. stress
      ≈97 bpm; HR is WESAD's single strongest feature, Cohen's d = +1.61 — currently unused
      because PP1 had no way to sense it). Gate on signal quality (motion/lighting) like the
      pose-visibility gate; emit "unavailable" when poor. Validate against UBFC-Phys BVP
      ground truth (dataset-only, no device). ~4–6 days.
- [ ] **PERCLOS for Driving mode** (% of time eyelids ≥80% closed over 60 s) — the standard
      drowsiness metric; ~20 lines on top of existing EAR. Lets Driving mode cite an
      established metric.
- [ ] (Stretch) Pixel-based temporal branch on a face/affect-pretrained backbone
      (VGGFace2 / AffectNet-finetuned) instead of frozen ImageNet — closes the loop the paper
      already flags as future work.
- [ ] Architecture cleanup (~2 days): move CNN + rPPG inference off the Streamlit main loop
      onto a background thread with a latest-result mailbox. Smoother demo, removes the
      "every 3rd frame" seam.

## Phase 3 — Learned decision layer (~1.5–2 weeks) — the "AI-powered" core

- [ ] **START THE LABELING LOOP IN WEEK 1** (calendar-bound, not effort-bound): add an
      end-of-session self-report prompt ("how stressed did you feel? 1–5") stored in
      `sessions.db` (existing migration pattern covers the schema change).
- [ ] **Meta-learner replaces hand-tuned fusion.** Train logistic regression /
      gradient-boosted trees over all branch outputs (behavior signals, CNN, rPPG, temporal
      model) on labeled evaluation CSVs → learned weights instead of hardcoded 0.20/0.80 and
      +0.12 boost. Still fully interpretable (coefficients / feature importances over named
      features) — the interpretability story survives.
- [ ] **Continual adaptation:** `retrain_from_sessions.py` periodically updates the
      meta-learner from accumulated (features, self-report) pairs via incremental fitting
      (`SGDClassifier.partial_fit`), with versioned model files. Deliverable claim:
      before-adaptation vs. after-N-sessions comparison. Frame honestly as
      *personalized incremental adaptation of the fusion/calibration layer*, not online deep
      learning.
- [ ] **Uncertainty/abstention:** calibrated confidence output; when low (bad lighting,
      occlusion, rPPG unavailable) display "uncertain" instead of forcing a level.
- [ ] Intervention effectiveness tracking (Feature 3) — same DB plumbing, log suggested
      breaks, compare stress index 5 min before vs. after.

## Phase 4 — Full reconciled re-evaluation (~1 week)

- [ ] ONE script regenerates EVERY number that appears in the paper/report, from scratch:
      DaiSEE test split, WESAD LOSO, UBFC-Phys correlation, temporal model old vs. new,
      learned vs. hardcoded fusion, all context modes with data, multi-subject table with
      per-subject breakdown, frame- AND session-level metrics with Wilson CIs.
- [ ] **Ablation table** — each branch removed one at a time (behavior / CNN / rPPG /
      temporal / rule boost / smoothing). This becomes the strongest results artifact.

## Phase 5 — Polish & deliverables (~3–5 days, overlaps Phase 4)

**No report/paper editing.** If a PP2 write-up is required later, everything it needs is
already produced by Phase 4's harness — pull numbers from the canonical results file only.

- [ ] Longitudinal analytics dashboard (Feature 5) — weekly trends, time-of-day patterns,
      per-context comparison. Makes the SDG-3 "see your patterns over time" claim visible in
      the demo.
- [ ] Session PDF report export (Feature 6).
- [ ] Ethics & privacy statement in the README: all processing on-device, no frames stored
      (only derived scalars in SQLite), user-initiated sessions only. Our architecture
      already earns this — say so.
- [ ] Update `code/README.md` to match reality (it is the one doc we DO maintain — it ships
      with the code). Fix the two claims that are currently false there: threshold
      auto-loading, and the smoothing-window source.
- [ ] Demo rehearsal against the Phase-4 numbers.

### If a PP2 write-up IS needed later
Carry forward from the audit section above: use only reproducible numbers, one value per

MediaPipe FaceMesh (not Haar cascade), and report CIs + session-level results. Keep the
FER2013 and original-LSTM negative results — they are good methodology. Add the new-LSTM
outcome in the same honest style, positive or negative.
