# Vision-Based Behavioral Stress Detection

Real-time cognitive stress monitoring from an ordinary laptop webcam — no wearables, no
contact sensors. Classifies stress as **LOW / MODERATE / HIGH** by fusing a DaiSEE-trained
CNN ensemble with an interpretable MediaPipe behavioral feature engine, with decision
boundaries anchored to the WESAD physiological reference dataset.

## How it works

```
Webcam (640x480, ~30fps)
   |
   +-- MediaPipe FaceMesh (468 landmarks) + Pose (33 landmarks)
         |
         +--> DaiSEE CNN ensemble (MobileNetV2 + EfficientNetB0)     weight 0.20
         |      re-centered against a 20-second personal baseline
         |
         +--> Behavioral feature engine                              weight 0.80
                EAR, blink rate, brow tension, jaw tension,
                head instability, neck strain, slouch
                        |
                        v
         Task-aware weighted fusion (Default / Studying / Hospital / Driving)
              + multi-signal rule boost (+0.12 when 4+ signals active)
              + 60-frame temporal smoother
              + 3-frame hysteresis level confirmation
                        |
                        v
                LOW / MODERATE / HIGH  -->  Streamlit dashboard + SQLite history
```

Two offline stages produce reusable artifacts: CNN training on DaiSEE, and WESAD
leave-one-subject-out calibration. One online stage runs per session: a 20-second personal
baseline calibration that re-centers both branches against the individual user.

## Results

Every number below is regenerated by one script — **`python run_all_evaluations.py`** — which
writes a timestamped file to `evaluation_data/`. Nothing here is transcribed by hand.

| Evaluation | n | Result | 95% CI |
|---|---|---|---|
| Live system, Default mode (single subject, own webcam) | 224 frames (100 relaxed + 124 stressed) | **99.11%** | [96.8%, 99.8%] |
| Live system, Studying mode (single subject) | 293 frames (147 + 146) | **94.54%** | [91.3%, 96.6%] |
| **Cross-subject (UBFC-Phys, 10 subjects), hand-tuned fusion** | 123,728 frames, LOSO | **55.19%** | — |
| **Cross-subject, learned fusion (logistic / gradient boosting)** | same data, LOSO | **66.74% / 77.06%** | — |
| rPPG heart rate vs Empatica E4 BVP (POS method) | 15 traces | **3.52 bpm** mean abs. error | — |
| WESAD physiological validation (LOSO, 15 subjects) | 877 windows | **91.86%** (F1 0.874) | — |
| DaiSEE CNN ensemble, held-out test split | — | ~82-84% | — |

The gap between 99.11% (single-subject) and 55.19% (cross-subject) is the central finding of
the PP2 work so far: hand-tuned constants measure the person they were tuned on. Learning the
fusion weights recovers +11 to +22 points out-of-fold, and the calibration fixes it prompted
(posture baseline, relative blink threshold, calibrated blink rate) are regression-tested.

Default mode: relaxed→LOW recall 100% (100/100), stressed→MOD/HIGH recall 98.39% (122/124).
Discrimination gap **+0.320** (relaxed mean 0.235 vs stressed mean 0.554).

**Read these honestly.** Three caveats, all of which the harness prints alongside the numbers:

1. These are **frame-level** accuracies. Frames within one recording are heavily
   autocorrelated, so frame-level *n* overstates the evidence. At **session level** — the
   honest denominator — it is 4/4 recordings, whose 95% CI is [51%, 100%]. Both are reported.
2. All live recordings are from a **single subject**, so this measures within-subject
   behaviour, not cross-user generalisation. Multi-subject evaluation is Phase 1 of the plan.
3. The Default-mode figure rose from 98.9% (n=176) once a typo'd filename
   (`relaaxed_2.csv`) was fixed — it had silently excluded 48 valid relaxed samples from
   every number previously reported.

### Documented negative results

- **FER2013 emotion branch — removed.** A/B evaluation showed including it *reduced* live
  accuracy (82.4% with vs 89.1% without). Scripts kept in `code/_archive/` for reproducibility.
- **CNN+LSTM temporal branch — disabled.** Trained on 5,356 DaiSEE sequences; reached 71.1%
  test accuracy, *below* the 86.6% trivial-majority-class floor. It collapsed to the majority
  class because frozen ImageNet features are not stress-discriminative. Wired into the fusion
  with weight 0.0. PP2 retrains it on behavioral feature sequences instead of raw pixels.

## Setup

### 1. Dependencies

Python 3.11 on Windows 10/11, plus a webcam.

```bash
pip install -r requirements.txt
```

The versions are pinned deliberately — MediaPipe 0.10.14 requires protobuf 4.25.3, and
TensorFlow 2.15 requires numpy < 2. Changing one usually breaks another.

### 2. Datasets — not included in this repo

Both are licensed research datasets that must be obtained from their original authors, and
together they are ~33 GB. Download them yourself and place them as shown:

- **DaiSEE** (9,068 e-learning video clips, 4 affect annotations) — Gupta et al., 2016.
  Request from the authors at IIT Hyderabad.
- **WESAD** (15 subjects, chest+wrist physiological recordings) — Schmidt et al., 2018.
  Available from Universität Siegen.

```
datasets/
  DaiSEE/DataSet/{Train,Validation,Test}/    raw clips
  DaiSEE/Labels/*.csv                        affect annotations
  WESAD/S{2..17}/S*.pkl                      physiological recordings
  processed_daisee/                          generated by daisee_preprocessing.py
```

### 3. Trained models — included, via Git LFS

`daisee_mobilenet_stress.h5` (29 MB) and `daisee_efficientnet_stress.h5` (21 MB) are tracked
with **Git LFS**, so a normal `git clone` fetches them automatically as long as Git LFS is
installed. If you cloned before installing it, or the files look like small text stubs:

```bash
git lfs install && git lfs pull
```

They are in LFS rather than committed directly so that retraining does not accumulate a new
50 MB copy in git history every time. To regenerate them from scratch instead (requires the
full DaiSEE dataset and several hours):

```bash
cd code && python daisee_preprocessing.py && python rebucket_to_binary.py && python train_daisee_stress.py
```

The system degrades gracefully without them — `app.py` loads what it finds, and the fusion
redistributes the DaiSEE branch weight to the behavioral branch if the models are absent.

## Running

```bash
cd code && streamlit run app.py
```

Then: pick a context mode → **Calibrate** (sit relaxed, 20 seconds) → **Start** → **Stop**
(auto-saves to the session history database).

All paths in the code are relative, so commands **must** be run from `code/`. If you use
VS Code, the committed `.vscode/launch.json` handles this — just press F5.

### Regenerating the evaluation numbers

```bash
cd code && python run_all_evaluations.py
```

This regenerates **every** number in this README into a timestamped file under
`evaluation_data/`. Nothing is transcribed by hand. (`analyze_sessions.py` still exists
for a quick single-folder check.)

### Running the tests

```bash
python -m pytest code/tests -v
```

41 tests covering session persistence, fusion maths, the behavioral heuristics, and
export naming. The key one compares Default-mode fusion output against the archived
pre-task-aware implementation in `code/_archive/` — the difference is exactly zero.

### Recording new evaluation sessions

Follow [`RECORDING_PROTOCOL.md`](RECORDING_PROTOCOL.md). Set the Subject ID and
Condition in the app's sidebar **before** recording; the export filename is generated
from them, so provenance cannot be lost afterwards.

---

## Privacy

All processing happens on-device. No video frames are ever stored — only derived scalar
values (stress index, level, branch scores) go into the local SQLite database. Sessions are
user-initiated. The session database is gitignored and never leaves the machine.
